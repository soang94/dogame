# 우리 강아지 · dogame

내 강아지 사진을 얼굴로 사용하는 iPhone용 2D 돌보기 앱의 첫 버전입니다. React Native + Expo SDK 57, TypeScript를 사용합니다.

## 구현한 기능

- SVG로 그린 잔디 마당과 둥근 강아지 몸통. 배경과 캐릭터는 `src/Scene.tsx`에서 분리했습니다.
- 사진 보관함에서 사진 선택, 드래그로 얼굴 위치 조정, 확대·축소(100–300%), 원형 얼굴 적용.
- 밥 주기(포만감 +18), 쓰다듬기(행복 +12), 재우기·깨우기, 하트와 간단한 움직임.
- 앱이 활성 상태인 동안 포만감은 분당 2, 행복은 분당 1 감소합니다. 에너지는 깨어 있으면 분당 2 감소하고 잠들면 분당 12 회복합니다. 상태 범위는 0–100입니다.
- 잠자는 동안 밥 주기와 쓰다듬기는 중지합니다. 사진 변경은 가능합니다.
- 앱을 백그라운드로 전환하거나 종료하면 시간 변화가 멈춥니다. 재실행 시 저장된 상태로 이어집니다.
- 상태는 AsyncStorage, iPhone 사진 파일은 앱 문서 디렉터리에 저장합니다. 외부 서버로 업로드하지 않습니다. 브라우저 검증에서는 사진을 data URL로 저장합니다.
- 처음에는 기본 그림 강아지가 표시됩니다. 사진을 선택하지 않아도 돌볼 수 있습니다.

배경 제거, 로그인, 알림, 배경 선택, 여러 견종의 몸통, 산책·미니게임은 아직 포함하지 않습니다. 실제 얼굴 표정은 정지 사진이며, 간단한 몸 움직임으로 반응합니다. 사진 교체 저장이 성공하면 이전에 앱에서 복사한 사진 파일을 정리합니다. 사진 보관함의 원본은 삭제하지 않습니다. 저장에 실패하면 이전 사진을 유지하고 다시 시도할 수 있습니다.

## 맥북에서 iPhone으로 테스트하기

1. 이 프로젝트 폴더를 맥북에 내려받고 압축을 풉니다.
2. 폴더 안의 `Start-on-Mac.command`를 엽니다. Node.js가 없거나 오래된 경우 공식 다운로드 사이트가 열립니다. Node.js 24 이상을 설치한 뒤 파일을 다시 엽니다.
3. iPhone의 App Store에서 **Expo Go**를 설치합니다. Expo Go를 맥북에 설치하는 것이 아닙니다.
4. 맥북과 iPhone을 같은 Wi-Fi에 연결합니다.
5. 실행 창의 QR 코드를 iPhone 카메라로 스캔하고 Expo Go로 엽니다. 게임을 테스트하는 동안 실행 창을 열어둡니다.

macOS에서 `.command` 실행 권한 오류가 나면 터미널에서 프로젝트 폴더로 이동한 뒤 `bash Start-on-Mac.command`로 실행할 수 있습니다. macOS 실행 도우미는 이 Linux 환경에서 실제 실행을 검증할 수 없으므로 Mac에서의 추가 확인이 필요합니다. 회사·공공 Wi-Fi에서 기기 사이 연결이 차단되면 개인 Wi-Fi로 시도합니다. 다른 앱으로 전환했다 돌아왔을 때 상태가 갑자기 줄지 않는지, 사진과 상태가 재실행 후에도 유지되는지 확인합니다.

## 개발 시작

Node.js 24와 npm을 사용합니다(`.nvmrc`).

```sh
npm ci
npm start
```

iPhone에 프로젝트 SDK와 호환되는 Expo Go를 설치하고 개발 서버의 QR 코드를 스캔합니다. 휴대폰에서 개발 서버에 접근할 수 있는 네트워크가 필요합니다. 클라우드의 localhost 주소나 QR 코드가 iPhone에서 바로 접속된다고 가정하지 마세요. 같은 Wi-Fi의 개발 컴퓨터에서 실행하는 것이 가장 단순합니다. iOS 시뮬레이터에는 macOS와 Xcode가 필요합니다.

첫 실행에서는 사진 없이 돌보기 → 사진 선택·조절 → 저장 → 앱 재실행 → 홈 화면에 나갔다 돌아오기 순서로 확인합니다. 사진 권한, 기기 내 파일 복사, 터치 동작, 종료·재실행은 실제 iPhone에서 추가 확인해야 합니다.

## 검증

```sh
npm run typecheck
npm test
npm run export:ios
npm run export:web
```

`export:ios`는 iOS JavaScript/Hermes 번들 검증입니다. 서명된 앱이나 IPA를 만드는 네이티브 빌드가 아닙니다. 앱스토어 배포는 추후 Apple 개발자 계정과 EAS/Xcode 설정이 필요합니다.

브라우저 기능 검증은 Chromium이 설치된 환경에서 수행할 수 있습니다. 첫 터미널에서 정적 서버를 실행하고 두 번째 터미널에서 테스트합니다.

```sh
npm run export:web
python -m http.server 8080 --bind 127.0.0.1 --directory dist
```

```sh
npm run test:browser
```

`CHROMIUM_PATH`로 Chromium 실행 파일을, `SMOKE_URL`로 검증할 서버 주소를 지정할 수 있습니다. 기본값은 `/usr/bin/chromium`, `http://127.0.0.1:8080`입니다. 테스트는 새 브라우저 프로필에서 돌보기, 수면 중 버튼 제한, 상태 복원, 사진 선택·확대·저장·복원, 활성 시간 변화, 백그라운드 중지·재개, 사진 저장 실패 복구, 작은 화면의 버튼 표시를 확인합니다. 사진 테스트에는 프로젝트 아이콘을 사용합니다. 결과 화면은 무시되는 `.expo/browser-smoke.png`에 저장됩니다.

## 이 클라우드에서의 실행

기본 사용자 캐시 경로가 읽기 전용이므로 npm 캐시를 `/tmp`에 둡니다. Expo의 외부 버전 조회가 차단되는 경우, 설치된 SDK의 호환성 정보를 사용하는 오프라인 CLI 모드로 실행합니다. npm 다운로드는 계속 TLS와 패키지 무결성 검증을 사용합니다.

```sh
npm_config_cache=/tmp/dogame-npm npm ci
EXPO_NO_TELEMETRY=1 EXPO_OFFLINE=1 npm start -- --host localhost --port 8081
```

다른 검증 명령에도 필요하면 `EXPO_NO_TELEMETRY=1 EXPO_OFFLINE=1`을 붙입니다. React Native DevTools 다운로드가 기본 캐시 경로 때문에 실패할 때 CLI가 제공하는 fallback을 사용합니다. 이 환경에서는 iPhone 실기기 연결 및 네이티브 iOS 빌드를 검증하지 않았습니다.
